## MODIFIED Requirements

### Requirement: Calculate portfolio holdings from strategy signals
The system SHALL calculate target holdings for requested trading dates from persisted successful
strategy signals whose `strategy_id` and `config_version` match the requested strategy identity.
When the caller supplies a `signal_ids` collection, the holdings calculation SHALL consider ONLY
signals whose `id` is in that collection (the signals produced by the specific backtest run) and
SHALL NOT fall back to global latest-wins selection across runs. An explicitly supplied empty
collection SHALL produce empty holdings. Only when `signal_ids` is `None` is the existing global
latest-wins selection preserved for backward compatibility.

#### Scenario: Apply the latest prior signal on the next trading date
- **WHEN** backend code calculates holdings for a trading date T and a matching successful strategy
  signal exists on an earlier trading date
- **THEN** the snapshot for T uses the latest matching signal with `signal_date` strictly before T
- **AND** each holding uses that signal position's target weight
- **AND** signals belonging to other strategies or config versions are ignored

#### Scenario: Calculate daily holdings from a signal
- **WHEN** backend code calculates holdings for a trading date T for which a matching successful
  strategy signal exists with `signal_date` strictly less than T
- **THEN** the returned holding snapshot for date T includes each such signal position ETF
- **AND** each holding uses that signal position's target weight

#### Scenario: Signal is not applied on its own as-of date
- **WHEN** backend code calculates holdings for a trading date T that equals a matching successful
  strategy signal's `signal_date`
- **THEN** the snapshot for T does NOT use that same-day signal
- **AND** the snapshot uses the latest matching successful signal with `signal_date` strictly
  before T, or empty holdings if none exists

#### Scenario: Calculate interval holdings by carrying positions forward
- **WHEN** backend code calculates holdings for an ordered interval of trading dates with matching
  successful strategy signals on some dates
- **THEN** the returned snapshots cover every requested trading date
- **AND** dates strictly after a signal date use that latest signal's target holdings until a later
  matching successful signal date is reached

#### Scenario: Empty holdings before first signal
- **WHEN** a requested trading date has no matching successful strategy signal with `signal_date`
  strictly before it
- **THEN** that date has empty holdings

#### Scenario: Carry prior signal into requested interval
- **WHEN** a requested trading-date interval starts after an earlier matching successful strategy
  signal
- **THEN** the first requested date uses the earlier signal's target holdings

#### Scenario: Rebalance date changes holdings explicitly
- **WHEN** backend code calculates holdings for dates before, on, and after a later matching
  successful strategy signal
- **THEN** the date before the later signal and the later signal's own date keep the previous
  holdings
- **AND** dates strictly after the later signal use the later signal's target holdings

#### Scenario: Latest successful signal run wins
- **WHEN** no `signal_ids` is supplied and multiple matching successful strategy signal runs exist
  for the same signal date, strategy id, and configuration version
- **THEN** holding calculation uses the run with the newest `generated_at` timestamp and id
  tie-breaker for that date

#### Scenario: Ignore failed signals
- **WHEN** a failed matching strategy signal exists on a requested trading date
- **THEN** holding calculation does not use that failed signal to change holdings

#### Scenario: Holdings scoped to caller-provided run signal ids
- **WHEN** backend code calculates holdings and the caller supplies a `signal_ids` collection
- **THEN** the calculation considers only signals whose `id` is in `signal_ids`
- **AND** signals outside `signal_ids` (including newer runs for the same `signal_date`) are ignored
- **AND** for each trading date, the position is derived from the signal in `signal_ids` with the
  largest `signal_date` strictly before that date

#### Scenario: Explicit empty run signal ids produce empty holdings
- **WHEN** backend code calculates holdings and the caller supplies an empty `signal_ids` collection
- **THEN** every requested date has empty holdings
- **AND** the calculation does not select signals outside that collection
- **AND** the calculation does not fall back to global latest-wins selection

#### Scenario: Rerun produces independent holdings
- **WHEN** two backtest runs for the same strategy, config version, and date range supply disjoint `signal_ids`
- **THEN** each run's holdings depend only on its own signals
- **AND** the holdings of one run are not affected by signals generated by the other run
